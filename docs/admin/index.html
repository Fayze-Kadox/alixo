Accès IA Qwen3.8-27B

Réservoir de clés et distribution aux utilisateurs.

Le modèle est ouvert (Qwen3.8-27B, Apache 2.0) ; chaque entrée du réservoir dit où il tourne (OpenRouter, Alibaba Cloud Model Studio ou un serveur à vous) et avec quelle clé. Les accès sont distribués aux utilisateurs : chacun reçoit un accès (serveur, modèle, clé), écrit dans keys/{uid} et lisible par lui seul. L’application l’utilise automatiquement s’il n’a pas de clé personnelle (« Imposer » la remplace même s’il en a une).

Distribution

Annonces et version

Ce que voient tous les utilisateurs dans la cloche de l’application.

Les annonces apparaissent dans la cloche de l’application de chaque utilisateur connecté (une seule fois, même après réinstallation). La version annoncée déclenche « Alixo x.y.z est disponible » (cloche et fenêtre de mise à jour) sur toutes les plateformes.

Version disponible

Toute version plus ancienne que la version disponible reçoit une fenêtre « Mise à jour disponible » au démarrage (rappel toutes les 6 h, « Plus tard » la fait taire 24 h). En dessous de la version minimale, la fenêtre est bloquante : l’application n’est plus utilisable avant la mise à jour.

Offre Alixo+ affichée

Prix et lien de paiement montrés dans la fenêtre « Passer à Alixo+ » (Paramètres › Alixo+, fonctions verrouillées). Sans lien, l’application indique que l’abonnement s’active par l’administrateur. L’activation elle-même se fait dans Utilisateurs › Alixo+… (avec une durée), une fois le paiement reçu.

Clés Alixo+

Clés d’activation à usage unique et versions personnalisées.

Une clé Alixo+ s’active dans l’application (Paramètres › Alixo+ › Clé d’activation) : elle ouvre Alixo+ sur le compte qui la saisit, pour la durée choisie (prolongation si Alixo+ est déjà actif). Chaque clé ne sert qu’une fois. Les clés inutilisées peuvent être supprimées.

Versions personnalisées (codées dans le code source)

Ces clés ne sont pas dans la base : elles sont écrites dans app/js/editions.js (code, nom, note, actif). Saisies dans l’application, elles activent la version personnalisée correspondante (toutes les fonctions ouvertes, nom affiché dans les Paramètres). Pour en ajouter ou en retirer, modifiez ce fichier puis publiez une nouvelle version.

Administrateurs

Qui peut ouvrir ce panneau.

Un administrateur peut voir les utilisateurs, attribuer des clés, activer Alixo+, suspendre des comptes et publier des annonces. Il ne peut pas lire le contenu des cours (les règles Firestore le lui interdisent). Chaque action faite ici (suspension, Alixo+, clé IA, message, export, consultation de la base) est inscrite dans le journal audit, consultable dans l’onglet Base de données.
